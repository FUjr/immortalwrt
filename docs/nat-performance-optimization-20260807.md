# MT7621 NAT 与 MAC 策略性能回归报告

测试时间：2026-08-07 UTC

## 测试拓扑

- WAN 测试端：本机 `enp6s18`，`10.96.210.226/24`。
- 网关：Misectel 7621EVB，WAN `10.96.210.253/24`。
- 临时 1:1 NAT：`10.96.210.251` 到 `vrf2/192.168.10.101`。
- LAN 测试端：RTL8152 `enx00e04c360eeb`，100 Mbps Full Duplex，MAC
  `00:e0:4c:36:0e:eb`。
- RTL8152 被放入独立 Linux 网络命名空间，避免 WAN 客户端与 LAN 服务端
  在同一协议栈中发生本地短路。LAN 端运行独立 `iperf3` 服务。
- 硬件和软件 flow offload 均保持关闭。

## 测试方法修正

旧脚本以 `7.68 Mbps / 64-byte UDP` 发送，理论值恰好是 15000 pps，
测试时长和调度取整会使接收统计稳定少约 2 pps。本轮把激励提高到
`7.75 Mbps`，理论值约 15137 pps，并在连续 iperf 会话间等待 2 秒，避免
服务端控制连接未释放导致正向或反向测试被重置。

该修正只改变测试激励和会话编排，不改变网关数据面。对应 feed 提交为
`9039802`。

## CPU 与 UDP 调优对照

所有对照均保持 NAT、VRF、物理路径和 MAC 配置不变。当前固件使用以太网
IRQ CPU1、RPS CPU2、按 CPU 分配 XPS 队列的方案。

| 配置 | 小包 PPS | 正向 Mbps | 反向 Mbps | Ping 平均/最大 ms | 结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| 当前分核基线 | 14998.18 | 94.76 | 94.77 | 1.307/1.799 | 保留 |
| 关闭 RPS | 14998.29 | 94.78 | 93.39 | 1.435/12.294 | 回退，不采用 |
| 基线加 UDP GRO forwarding | 14997.88 | 92.75 | 93.08 | 1.773/14.597 | 回退，不采用 |

关闭 RPS 会降低反向吞吐并增加延迟；UDP GRO forwarding 同时降低正反向
吞吐并扩大延迟尖峰。两项试验均已撤销，源码中的 release 13 分核策略无需
修改。端口统计未观察到 TxDrop、RxDrop 或 CRC 错误。

## 修订脚本结果

| 指标 | 默认 MAC 策略 | 完整 MAC 策略 | 门槛 |
| --- | ---: | ---: | ---: |
| UDP 64 字节小包 | 15134.87 pps | 15134.68 pps | >=15000 pps |
| 小包丢包率 | 0% | 0% | 记录项 |
| 正向 UDP | 94.78 Mbps | 94.76 Mbps | >=100 Mbps |
| 反向 UDP | 94.76 Mbps | 94.77 Mbps | >=100 Mbps |
| Ping 平均时延 | 1.222 ms | 1.178 ms | <1 ms |
| Ping 最大时延 | 1.474 ms | 1.524 ms | 记录项 |

完整 MAC 策略包括：LAN2 允许列表中只配置 RTL8152 MAC、`mac_limit=1`、
违规动作 `alert`，以及 enforcement 模式下针对
`192.168.10.101=00:e0:4c:36:0e:eb` 的四条 bridge IP-MAC 防欺骗规则。
策略运行期间动态 MAC 计数为 1，无非法 MAC 事件，防欺骗违规计数为 0。

完整 MAC 策略相对默认策略的 PPS 差异为 -0.19，正向吞吐 -0.02 Mbps，
反向吞吐 +0.01 Mbps，平均时延 -0.044 ms，均处于本次测量噪声范围内。
未观察到 MAC 策略导致持续吞吐或时延回退。

另外分别执行三轮、每轮 100 包的低间隔 Ping：默认策略平均值范围为
1.323-1.508 ms，端口 MAC 策略为 1.254-1.298 ms，完整 MAC 策略为
1.341-1.417 ms。三个区间有重叠，不能据此声称 MAC 策略产生稳定延迟增量。

## 与历史结果比较

2026-08-05 历史结果为 14998.02 pps、92.85/93.20 Mbps 和 2.673 ms。
本轮修订脚本默认策略结果分别改善 136.85 pps、1.93/1.56 Mbps，平均时延
下降 1.451 ms。由于本轮使用 LAN2、独立网络命名空间和修订后的 PPS 激励，
该比较能说明当前测试路径整体结果提升，但不能把全部增益归因于单一内核
调优参数。

严格判定为：15Kpps 已通过；正反向 100 Mbps 应用层有效载荷和平均时延
小于 1 ms 仍未通过。100 Mbps Fast Ethernet 的线路开销意味着 iperf UDP
有效载荷不能达到完整线速，但仍按客户给定门槛记录为未通过。

## 恢复与证据

网关的临时 NAT、端口 MAC 策略和 IP-MAC binding 在测试后恢复；RPS 与
UDP GRO 恢复为固件默认值。主机测试命名空间和 RTL8152 临时地址也在测试
结束后清理。

原始 `iperf3 --json`、Ping 输出和各组 Markdown 报告位于本轮交付压缩包，
不加入源码仓库或固件数据目录。
